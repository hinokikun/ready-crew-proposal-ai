# Responsibility Boundary

## Message Designer Owns

- What one slide should say
- Why that message is appropriate
- How evidence supports or limits the message
- Which missing evidence must be disclosed
- Whether the message is customer-facing enough to proceed

## Message Designer Does Not Own

- Slide type selection
- Deck length
- Evidence requirement planning
- Slide Blueprint
- Diagram
- Layout
- Theme
- Typography
- Rendering
- PPTX
- Beautiful.ai
- Frontend UI
- API
- DB persistence

## Upstream

- Phase 2A Deck Planner
- Phase 2B Evidence Planner

## Downstream

Phase 2D may use this output to create Slide Intent or Slide Blueprint inputs, but Phase 2C itself remains offline.
